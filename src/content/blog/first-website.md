我不太会写前端，这个网站最早是几页静态 HTML，后来才改成现在这个博客，域名是 [www.l-w.sryze.cc](https://www.l-w.sryze.cc/)。搭的时候发现，代码本身倒没怎么卡住，反而是后台设置里几个不起眼的开关折腾了我半天。

## GitHub Pages 的发布来源

网站托管在 GitHub Pages 上。有一回我把新版代码合进仓库了，可打开网址看到的还是老页面。查了半天，原来是仓库 **Settings → Pages** 里的发布来源（Source）还停在原来的分支上，没有切到 **GitHub Actions**。切过来的时候注意别把下面的自定义域名清掉了。

## 自定义域名别漏了 `CNAME`

我的域名 `www.l-w.sryze.cc` 早就解析到 GitHub Pages 了，仓库根目录也放着 `CNAME` 文件。换发布方式那次差点把域名栏搞丢，好在保留了原样，等几分钟重新部署完就恢复正常了。

## 为什么改完文章线上还没变

后来开始用 Pages CMS 写文章，也经常碰到「明明点保存了，刷新网页还是旧的」。前后踩过三次不同的坑：

1. **还在构建中**：静态站每次保存都会触发一次仓库构建，正常要等 30 到 60 秒才会生效，急着刷新肯定看不到。实在拿不准可以去仓库的 Actions 页面看一眼跑完没有。
2. **浏览器缓存**：构建早跑完了但页面没变，多半是本地缓存，Windows 按 `Ctrl+F5`（Mac 按 `Command + Shift + R`）强刷一下就行。
3. **压根没写进仓库**：有次以为文章格式写坏了，结果发现是 Pages CMS 没拿到仓库的写入权限。界面能打开不代表能提交，得在 GitHub 应用授权里勾上这个仓库才行。

把这几处顺清楚后，日常更新就省心多了，在后台写完预览保存，等一分钟就能上线。
