我是编程新手。这个网站最早是几页静态 HTML，后来换成现在的博客，域名是 [www.l-w.sryze.cc](https://www.l-w.sryze.cc/)。真正卡住我的，往往不是怎么写页面，而是设置页上那些不太显眼的选项。

## GitHub Pages 的发布方式

网站放在 GitHub 上，用 GitHub Pages 发布。改版的时候，仓库里的新代码已经准备好了，可是线上还是旧样子。原因很简单：Pages 的发布来源还停在原来的分支，没有改成 GitHub Actions。

这个开关在仓库的 Settings → Pages 里。改的时候，下面已经填好的自定义域名不要动。只合并代码、不改这一项，公开地址看到的就还是旧站。

## 自定义域名

域名本身早就指到 GitHub Pages 了。后来容易漏的是：换发布方式之后，自定义域名那一栏要保持原样。我用的是 `www.l-w.sryze.cc`，仓库里也有对应的 `CNAME` 文件。发布方式改对了、域名还在，过几分钟用自己的域名打开，才是新站。

## 改完为什么线上没变

后来写文章、改页面，还是会碰到「我明明存了，网站怎么还是旧的」。我至少遇到过三种情况。

第一种，其实还在发布。在写作后台点保存，仓库就会开始构建。最近几次大概 30 到 60 秒，一两分钟内会出现在网站上。它不是保存的那一瞬间立刻变，这是静态网站的正常节奏。进度可以在仓库的 Actions 里看。

第二种，浏览器还拿着旧页面。已经过了两分钟，可以强制刷新试试：Windows 用 `Ctrl+F5`，Mac 用 `Command + Shift + R`。

第三种，保存其实没有写进仓库。我有一次以为是文章写坏了，后来才发现写作后台能打开，却没有权限把文件写回 GitHub。需要先给 Pages CMS 这个应用授权，并勾上这个仓库，保存才会真的生效。编辑器能打开，不等于已经能写入。

这三件事弄清楚之后，这个网站就好维护多了。不会写多少代码，也可以自己更新：在后台写字、看一眼预览、再保存。剩下的，就是等一分钟，必要时刷新一下。
